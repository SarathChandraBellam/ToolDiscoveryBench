# Library docs

Use for API / usage questions about a library or framework.

- If a framework has its own dedicated docs tool (e.g. Astro docs, Svelte docs), prefer it:
  it is more specific than a generic docs tool.
- For other libraries, a version-aware docs service usually needs the library id resolved
  first (a *resolve library id* step), then a docs query.
- Svelte code that must be checked or fixed: use the Svelte autofixer; a shareable demo:
  the Svelte playground tool.
- Don't answer from memory when a docs tool is available: docs change between versions.
